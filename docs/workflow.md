# Workflow

## 开发步骤

1. 从 `main` 创建任务分支。
2. 确认目标服务和影响范围。
3. 修改代码、脚本或文档。
4. 运行 `make quick`、`make check` 或本地等价验证。
5. 提交并推送任务分支。

## 部署脚本

- 脚本应可重复执行。
- 不把生产 `.env`、证书和备份包提交到 Git。
- 修改迁移脚本时要说明回滚方式。
- 部署、重启、日志查看和数据排查由 Codex 通过 SSH 到服务器执行。

## 前后端联动

`neo_ai_chatroom` 前端、后端和网关路径必须保持一致。

## 部署与运行验证

- 正式部署前，优先确认代码已提交并推送到 GitHub 准源。
- Codex 通过 SSH 进入服务器部署目录，从 GitHub 准源同步代码。
- 部署前确认 `.env`、证书、数据库卷、上传文件、备份和日志不会被 Git 覆盖。
- 部署后检查 Compose 服务状态、网关访问、最近错误日志和本次改动相关页面/API。
